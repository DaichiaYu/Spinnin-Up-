# Spinnin-Up 訓練歷史（CSV v3）與交接

## 資料流程

1. 運動前：使用者只在選到的身體區域指定「今天想怎麼處理」，不先追問症狀或難度。
2. `src/ui.js` 開始播放時，抓取目標、所選部位意圖、實際課表的快照。
3. 運動完成：`src/screens.js` 顯示整體感受／困難度，必要時展開原先指定的部位；逐動作回報另設選填展開區。
4. 按「送出回報」或「這次先跳過」時，`src/workout-history.js` 產生單筆事件並附加到 `profile.history`。
5. 按「下載最新檔案」：`src/profile.js` 匯出既有基本資料、能力與調整，加上完整歷史到同一個 CSV。
6. 下次使用者上傳此 CSV，歷史重新讀回，首頁「訓練歷史」唯讀顯示。

## 歷史模型

每筆包含：
- `id`：連號 `w-000001` 起
- `at`：本次開始時間 ISO 8601
- `minutes`：完成時計算的經過分鐘數
- `trial`：是否試做
- `plan`：當時整體訓練目標、範圍、強度、場景、預計時間
- `intentions`：開始前各部位想怎麼處理
- `exercises`：實際開始播放的動作、秒數、組數、休息等快照
- `report.skipped`：是否略過問卷
- `report.overall`：做完的感受和難度（選填）
- `report.regions`：指定部位做完的感受／困難度（選填）
- `report.exercises`：逐動作詳細回報（選填）

不覆寫前一筆，不把事後自動調整的動作量改回原始課表快照。

## CSV 格式

`PROFILE_VERSION=3`。沿用原本的五欄 CSV；每筆歷史放在
`hist.w-000001` 等代號的行內，第三欄是 `encodeURIComponent(JSON.stringify(entry))`。

這只是為了用同一個 CSV 攜帶完整歷史，**不是加密、不是防竄改簽章**。使用者在網站裡無法修改或刪除過去紀錄，但手上有原始 CSV 的人仍能用外部工具編輯。現階段沒有登入、後端、可信簽章服務，不能提供真正的防竄改保證。

舊版 v1/v2 CSV 須能正常讀回，新版會附帶 `history: []`；毀損或無效的歷史行忽略並提醒，不應丟掉其他有效身體數值。

## 重要實作邊界

- `src/workout-history.js` 是歷史資料單一來源，保持純函式，不碰 DOM 或儲存空間。
- `src/screens.js` 的歷史畫面唯讀，不提供修改／刪除紀錄。
- 不使用 localStorage 保存身體資料或歷史；下載最新 CSV 是使用者唯一持久化方式。
- 訓練網址 `#r=` 仍然只放課表，不可塞入身體數值、回報、歷史。
- 當使用者略過問卷，仍記錄「何時完成、做了什麼」以及 `skipped=true`。
- 運動後的主觀感受不自動當成醫療診斷；已明確回報某動作疼痛，維持原本停止該動作的規則。
- 未審核的外部 candidate exercise 不可接進正式課表。

## 測試與後續驗收

執行 `node --test tests/js/*.test.mjs`，特別是 `tests/js/workout-history.test.mjs`、`tests/js/recovery.test.mjs`。

手機需要親自測：
- 指定頭頸想放鬆，不再事先選緊／痠／痛
- 做完看見可略過的感受／困難度
- 下載 CSV，下次上傳，能查看同一筆紀錄
- 重複訓練產生第二筆，第一筆不被改寫
- 點開歷史沒有任何編輯或刪除入口
- 舊版 CSV 仍能讀入
