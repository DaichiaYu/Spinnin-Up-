# 決策紀錄

新的決定加在最上面。每一條寫：決定了什麼、為什麼。

## 已經決定

### 2026-11-13（第 3 階段）

- 必填、建議填、可有可無的分法，表格用 CSV、超過 8 週提醒重新測量：使用者同意照預設。
- 試做動作：靠牆蹲、臀橋、彈力帶水平拉開（沒有彈力帶用毛巾）、90/90 仰躺核心。
- 回報第一題的選項：穩定做完／後半段姿勢跑掉／做不到預定的量。
- 以下是 AI 訂的規則，使用者說「先試用再看要不要留」：每次只調一小步、疼痛就停掉、排課表的比例和時間估法（細節見 `roadmap.md`）。

### 2026-11-13（實測後）

- **播報模式可以選**：語音＋提示音、只有提示音、全部靜音。理由：實測發現語音會暫時壓低影片的聲音；看影片時視線在螢幕上，用提示音加畫面變色就夠，沒看螢幕時再用語音。
- **播報時，對應的說明文字同步變色。**
- **語音和提示音的大小可以分開調**，不用調整整支手機的音量。
- 聲音設定記在瀏覽器裡，下次打開還在。這不是身體資料。

### 2026-11-13

- **正式名稱是 Spinnin-Up**，Spin-Up 是內部簡稱。完整的計劃和期待記在私人倉庫 `DaichiaYu/Spin-Up` 的 `plan.md`，以那份為準。
- **不記錄人種。**
- **身體數據**：少數必填，其餘分「建議填」和「可有可無」，並說明每個數字可以算出什麼。用比例估出大概的體型傾向。
- **所有使用者都可以自己選「左右有沒有差」**；量到的左右差在 5% 以上時，跳出建議勾選。
- **資料不自動存。** 使用者可以下載空白表格、填好上傳；也可以下載一份「最新檔案」（含設定和試做結果），下次上傳就能接著用。檔案記下載時間，太久會建議重新測量。
- **建議頻率**有預設，使用者可以調整。
- **邊看影片**：不嵌影片，靠手機本身的小窗播放（子母畫面）。
- **動作清單**：現有的先當範例，另外加了用居家物品（毛巾、有重量的包包、矮階、枕頭）做的動作當範本。之後再增減。
- 器材資料加上 `substitute`（可以代替的東西）。

### 2026-11-12（第 1 階段）

- **產品定位**：居家、以「撐住」（等長）為主的訓練頁面。差異在三件事：看得懂每個動作在練哪裡、做完回報實際哪裡有感覺再調整、左右兩邊可以分開設定。
- **排課表的順序不是重點。** 只守三條：暖身在前、收操在後、同一個部位不連排兩個。力氣花在讓使用者看懂這組練了什麼。
  （依據：Fitbod 分析 150 萬組紀錄，照合理順序排的課表，第一個和第七個動作的重量差異平均只有 4%。）
- **了解使用者的方式**：身體尺寸 + 幾個試做動作的回報 + 過去的運動經驗和偏好 → 猜出起點；之後靠每次做完的回饋修正。不建立「居家測試的常模」。
- **尺寸只用來決定「該多問什麼」**，不直接下結論。尺寸分不出肌肉和脂肪。
- **偏好和能力分開用**：偏好決定形式（撐著的多還是動的多），能力決定難度和秒數。
- **回饋問兩題**：「做得怎麼樣」（具體選項）和「哪裡有感覺」（點部位）。拿「應該在哪裡有感覺」（`primary`）和「實際在哪裡有感覺」比，落差對到 `watch` 就知道怎麼調。
- **每次只調一小步**（秒數 ±5，或換上一級／下一級的動作）。連續兩三次同方向才調大。
- **左右不對稱**：先做到偵測差異 → 問使用者要一樣、分開設定、還是天生不同 → 提供一般性的調整選項 → 提醒洽物理治療師。
- **免帳號、連結、行事曆**：目的是初期不用存使用者資料，不是核心賣點。之後要換成帳號不影響核心。
- **動作圖用程式產生的 SVG 線稿**，風格一致、能標出發力位置。精緻插畫之後再說。
- **開發順序**：動作資料庫 → 預覽和編輯 → 播放器 → 連結和行事曆 → 初次問卷和規則 → 回饋調整。
- **停損點**：先只做給使用者自己用。用 3–4 週後再決定要不要做成產品。
